# 근무일정 → 휴대폰 캘린더 구독 (설정 절차)

`calendar_ics.gs` 는 근무일정표의 Firebase 데이터를 **캘린더 구독 파일(.ics)** 로 내보내는 중계입니다.
한 번 설정하면 각자 휴대폰 캘린더에 주소를 등록하고 끝입니다(읽기 전용).

> **이 스크립트는 만족도 Apps Script(`apps-script/survey_analysis.gs`)와 다른 프로젝트입니다.**
> 같은 프로젝트에 넣지 마세요. 그 프로젝트는 `clasp` 가 코드를 통째로 바꾸므로, 여기 코드를 넣으면
> 다음 자동 배포에서 지워집니다. 이 폴더에는 자동 배포가 걸려 있지 않습니다 — 사람이 붙여넣습니다.

## 1. Apps Script 프로젝트 만들기

1. <https://script.google.com> → **새 프로젝트**
2. 프로젝트 이름: `FSG 근무일정 캘린더`
3. 기본으로 생긴 `Code.gs` 내용을 **전부 지우고**, 이 폴더의 `calendar_ics.gs` 내용을 **전부** 붙여넣습니다.

## 2. 스크립트 속성 넣기

프로젝트 설정(왼쪽 톱니) → 아래 **스크립트 속성** → 속성 추가

| 속성 | 값 |
|---|---|
| `FB_API_KEY` | 근무일정표 화면의 `FIREBASE_API_KEY` 와 같은 값 (공개 웹 키라 비밀이 아닙니다) |

`FB_REFRESH` 는 스크립트가 처음 돌 때 **자동으로** 만들어 저장합니다(익명 계정을 매번 새로
만들지 않기 위한 값). 사람이 넣지 않습니다.

## 3. 소금(salt) 정하기 — Firebase 콘솔

사람별 주소를 추측할 수 없게 만드는 값입니다. **저장소에 두지 않습니다.**

1. 무작위 문자열을 하나 만듭니다(영문·숫자 24자 이상). PowerShell:
   ```powershell
   -join ((48..57) + (97..122) | Get-Random -Count 28 | % {[char]$_})
   ```
2. Firebase 콘솔 → Realtime Database → `work-schedule` 에서 **calendar** 를 추가하고 그 아래
   `salt` = 위에서 만든 값 (`url` 은 5번에서 넣습니다).

```
work-schedule
  └ calendar
      ├ salt : "k7q2..."
      └ url  : "https://script.google.com/macros/s/..../exec"
```

> DB 규칙(1단계)은 `work-schedule` 아래 허용된 경로(팀·teamRoster·notes)만 쓰기를 열어 두었고
> `calendar` 은 거기 없습니다 — 즉 **화면에서는 아무도 이 값을 고칠 수 없고**, 콘솔에서 넣는 값만
> 들어갑니다(콘솔은 규칙을 거치지 않습니다). 읽기는 `work-schedule` 의 `.read` 로 열려 있습니다.
> 규칙 파일은 고치지 않아도 됩니다.

## 4. 웹 앱으로 배포

**배포 → 새 배포 → 유형 「웹 앱」**

| 항목 | 값 |
|---|---|
| 설명 | `v1` |
| 실행 계정 | **나** (내 계정으로 실행) |
| 액세스 권한 | **모든 사용자** — 캘린더 앱은 로그인하지 않고 주소만 가져갑니다 |

배포 후 나오는 `.../exec` 주소를 복사합니다.

## 5. 주소를 Firebase 에 넣기

3번의 `work-schedule/calendar/url` 에 그 `/exec` 주소를 붙여넣습니다.

## 6. 확인

1. 편집기에서 함수 `checkSetup` 을 골라 **실행** → 실행 로그에 소금 유무, 명단 인원, 팀별 인원이
   나옵니다. 명단이 0명이면 근무일정표의 **팀원 관리**를 한 번 저장해 `teamRoster` 를 만듭니다.
2. 근무일정표를 새로 고치고 **캘린더 연동** 을 누르면 본인 주소와 팀 주소가 보입니다.
3. 주소를 브라우저에 붙여 열어 보면 `BEGIN:VCALENDAR` 로 시작하는 글이 내려옵니다.

## 휴대폰에 등록하는 방법 (사용자 안내)

- **아이폰** — 설정 → 캘린더 → 계정 → 계정 추가 → 기타 → **구독 캘린더 추가** → 주소 붙여넣기
- **안드로이드·구글 캘린더** — PC 브라우저에서 <https://calendar.google.com> → 왼쪽 「다른 캘린더」
  **＋** → **URL로 추가** → 주소 붙여넣기 (휴대폰 앱에는 이 메뉴가 없습니다)

갱신 시점은 **캘린더 앱이 정합니다**(보통 몇 시간, 구글은 더 늦을 때가 있습니다). 파일에
「4시간마다」 힌트를 넣어 두었지만 앱이 따르지 않을 수 있습니다. 급하게 확인할 일정은 일정표 화면을 봅니다.

## 알아 둘 것

- **읽기 전용**입니다. 캘린더에서 고쳐도 일정표에는 반영되지 않습니다.
- 담기는 기간은 **지난 30일 ~ 앞으로 120일**(`DAYS_BACK`·`DAYS_AHEAD`). 늘리면 받는 양도 늘어납니다.
- **주소를 아는 사람은 그 일정을 볼 수 있습니다.** 로그인이 없는 구독 방식의 한계입니다.
  단체 대화방에 올리지 말라고 화면에도 적어 두었습니다.
- **주소를 무효로 만들려면** `work-schedule/calendar/salt` 를 새 값으로 바꿉니다. 그러면
  **모든 사람의 주소가 한꺼번에 바뀌므로**, 각자 다시 등록해야 합니다(퇴사자 정리 등에 씁니다).
- 명단(`teamRoster`)에 없는 이름은 주소를 만들 수 없습니다. 화면도 그렇게 안내합니다.
- **요금**: 팀 하나 · 기간 한 토막만 받고 30분간 캐시합니다(`DATA_CACHE_SEC`). 구독자가 44명이어도
  Firebase 는 팀당 1시간에 두 번만 읽힙니다. 캐시 시간을 줄이거나 전체 데이터를 받게 고치면
  다운로드 요금이 바로 올라갑니다 — `CLAUDE.md` 「Firebase 사용량·요금」 참고.
- 코드를 고칠 때는 **이 파일을 고쳐서 다시 붙여넣고**, 배포 → 배포 관리 → 수정 → 새 버전을 올립니다.
  (만족도 프로젝트의 「새 버전 누르지 않기」 경고는 그 프로젝트에만 해당합니다.)
- 시험: 저장소 루트에서 `node tests/test_cal_sub.js` — 화면과 이 스크립트가 같은 열쇠를 쓰는지,
  .ics 형식과 캐시 동작을 확인합니다.

## 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 주소를 열면 「주소가 올바르지 않습니다」 | 명단(`teamRoster`)에 그 이름이 있는지, 소금을 바꾸지 않았는지 |
| 「스크립트 속성 FB_API_KEY 가 없습니다」 | 2번 단계 |
| 「데이터베이스 접근이 거부되었습니다 (401/403)」 | DB 규칙이 읽기를 막고 있는지, API 키가 맞는지 |
| 구글 캘린더에서 「URL로 추가」가 실패 | 주소를 브라우저로 먼저 열어 `BEGIN:VCALENDAR` 가 나오는지 확인. 그래도 안 되면 그 글을 `.ics` 파일로 저장해 「가져오기」로 넣습니다(자동 갱신은 안 됩니다) |
| 아이폰에 일정이 안 보임 | 캘린더 앱 → 캘린더 목록에서 구독 캘린더가 켜져 있는지 |
