# 근무일정표 → Google 캘린더 「FSG 근무일정 거울」 (설정 절차)


> **2026-11-25 — 매일 실행은 Apps Script 판으로 옮겼습니다** (`apps-script-calendar/mirror.gs`, 설치는 `apps-script-calendar/README.md` 「거울 캘린더」). GitHub 예약 실행이 4~8시간 밀리고 시크릿 4개·서비스 계정이 필요했기 때문입니다. 이 워크플로는 예약을 끄고 손으로 돌리는 것만 남겼습니다. 아래는 GitHub 판을 다시 쓸 때의 절차입니다(그때 `FIREBASE_API_KEY` 는 서버용 키 — `firebase/README.md` 「웹 API 키 정리」).

매일 05:30(한국 시간)에 GitHub Actions 가 근무일정표의 **오늘부터 7일치**를 읽어, 기본 근무가 아닌
상태(내근·회의·휴가·당직 등)를 Google 캘린더 하나에 종일 일정으로 복사합니다.
아침 브리핑(Google Calendar 를 읽는 예약 작업)이 이 캘린더를 보면 근무 상태가 같이 나옵니다.

- 읽기 전용 거울입니다. 캘린더에서 고쳐도 근무일정표에는 반영되지 않고, 다음 실행 때 다시 맞춰집니다.
- Firebase 에는 쓰지 않습니다. DB 규칙도 바꾸지 않습니다(읽기는 지금 규칙으로 됩니다).
- 휴대폰 구독(.ics, `apps-script-calendar/`)과는 별개입니다.

## 무엇이 들어가나

제목은 `이름 상태`(여러 개면 `이름 회의·내근`), 설명에 칸별 내용(오전1·오후1·야간 등)과 팀.

| 넣는 것 | 넣지 않는 것 |
|---|---|
| 휴가 · 오전 휴가 · 오후 휴가 · OFF · 당직 · 내근 · DP · 교육 · 회의 | 빈 칸 |
| 직접 입력한 내용(예: 건강검진) | `ON` (기본 근무) |
| 야간 칸: 석/야 · 석간 · 잔업 · 야간 OFF · 대전/광주/부산/대구당직 | 병원(거래처)명이 적힌 칸 — 방문은 기본 근무 |
| 주말 · 휴일 칸: 전화대기 · 당직(지역별) · 추가편성 · 기타 | |

병원명은 화면의 거래처 목록(`INSTITUTION_LIST`)과 일치할 때만 걸러집니다. 목록에 없는 병원명을
직접 입력한 칸은 「직접 입력」으로 보고 그대로 들어갑니다.

## 설정 (한 번만) — 약 15분

### 1. 거울 캘린더 만들기 (Google 캘린더, PC 브라우저)

1. <https://calendar.google.com> → 왼쪽 **다른 캘린더 +** → **새 캘린더 만들기**
2. 이름: **`FSG 근무일정 거울`** — 띄어쓰기까지 정확히. 이름이 다르면 동기화가 멈춥니다(다른 캘린더에 쓰지 않게 하는 장치).
3. 시간대: 서울 → **캘린더 만들기**

본인 계정으로 만들므로 본인 캘린더 목록에 바로 보이고, 따로 공유받을 필요가 없습니다.

### 2. 서비스 계정 만들기 (Google Cloud)

1. <https://console.cloud.google.com> → 위쪽 프로젝트 선택 → **새 프로젝트**(이름 예: `fsg-calendar-mirror`)
2. **API 및 서비스 → 라이브러리** → `Google Calendar API` 검색 → **사용**
3. **IAM 및 관리자 → 서비스 계정 → 서비스 계정 만들기** → 이름 예: `calendar-mirror` → 만들기(역할은 주지 않아도 됩니다) → 완료
4. 만든 계정을 눌러 **키 → 키 추가 → 새 키 만들기 → JSON** → 파일이 내려받아집니다.
5. 서비스 계정의 **이메일**(`calendar-mirror@....iam.gserviceaccount.com`)을 복사해 둡니다.

> 키 파일은 비밀번호와 같습니다. 메일·메신저·저장소에 올리지 말고, 4번에서 GitHub 에 넣은 뒤 PC 에서 지웁니다.
> 「서비스 계정 키 생성이 조직 정책으로 막혀 있다」고 나오면 개인 Gmail 계정의 프로젝트에서 만듭니다.

### 3. 거울 캘린더를 서비스 계정에 공유

1. Google 캘린더 → 왼쪽 `FSG 근무일정 거울` 옆 **⋮ → 설정 및 공유**
2. **특정 사용자 또는 그룹과 공유 → 사용자 및 그룹 추가** → 2-5 의 서비스 계정 이메일 → 권한 **일정 변경** → 보내기
3. 같은 화면 아래 **캘린더 통합 → 캘린더 ID**(`...@group.calendar.google.com`)를 복사합니다.

기존 캘린더(설치팀 일정 등)는 공유하지 않습니다 — 서비스 계정은 공유받은 이 캘린더에만 닿습니다.

### 4. GitHub Secrets 넣기

저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 |
|---|---|
| `FIREBASE_API_KEY` | `work-schedule.html` 의 `FIREBASE_API_KEY` 값 |
| `FIREBASE_DB_URL` | `work-schedule.html` 의 `FIREBASE_URL` 값 (`https://...firebaseio.com`) |
| `GOOGLE_SERVICE_ACCOUNT_KEY` | 2-4 에서 받은 JSON 파일을 메모장으로 열어 **내용 전체** |
| `MIRROR_CALENDAR_ID` | 3-3 의 캘린더 ID |

### 5. 처음 돌려 보기

이 워크플로 파일이 `main` 에 있어야 돕니다(PR 머지 후).

1. 저장소 → **Actions → 근무일정 거울 캘린더 동기화 → Run workflow**
2. 초록 체크가 뜨면 로그에 `거울 캘린더: 새로 n · 고침 n · 삭제 n · 그대로 n` 이 보입니다(이름은 찍지 않습니다).
3. Google 캘린더에서 `FSG 근무일정 거울` 에 일정이 생겼는지 확인합니다.

그 뒤로는 매일 05:30 에 자동으로 돕니다(GitHub 사정으로 몇 분~수십 분 늦을 수 있습니다).

## 실패했을 때

실패하면 워크플로가 빨간색으로 끝나고 GitHub 가 메일로 알립니다. 로그 마지막 줄 `동기화 실패: ...` 를 봅니다.

| 메시지 | 원인 · 조치 |
|---|---|
| `GitHub Secret ○○ 이(가) 비어 있습니다` | 4번의 그 값이 없음 |
| `GOOGLE_SERVICE_ACCOUNT_KEY 가 JSON 형식이 아닙니다` | 키 파일 내용 전체(`{` 부터 `}` 까지)를 넣지 않음 |
| `Google 로그인 실패 (HTTP 400/401)` | 키가 삭제·만료됨 → 2-4 에서 새 키를 만들어 다시 넣기 |
| `거울 캘린더 확인 실패 (HTTP 404)` | 캘린더 ID 가 틀렸거나 3번 공유를 안 함 |
| `거울 캘린더 확인 실패 (HTTP 403)` | Calendar API 를 켜지 않음(2-2) |
| `「FSG 근무일정 거울」 캘린더가 아닙니다` | 캘린더 이름이 다르거나 다른 캘린더 ID 를 넣음 |
| `일정 만들기 실패 (HTTP 403)` | 공유 권한이 「일정 변경」이 아님 |
| `Firebase 익명 로그인 실패` | `FIREBASE_API_KEY` 가 틀렸거나 익명 로그인이 꺼짐 |
| `근무일정 읽기(팀) 실패 (HTTP 401)` | DB 규칙이 바뀌어 읽기가 막힘 |
| `읽은 칸이 0건인데 거울에는 일정이 n건` | 읽기가 비정상 — 거울을 지우지 않고 멈춘 것. `FIREBASE_DB_URL` 확인 |
| `거래처 목록(INSTITUTION_LIST)을 찾지 못했습니다` | `work-schedule.html` 의 그 상수 이름·형식이 바뀜 → `mirror.js` 의 `loadInstitutions` 를 맞춘다 |

실패한 날은 거울이 전날 상태로 남습니다(지워지지 않습니다). 고친 뒤 **Run workflow** 로 다시 돌리면 됩니다.

## 동작 방식 (바꿀 때 알아 둘 것)

- **읽기**: 팀 6개에 `work-schedule/{팀}` 을 날짜 키 범위(오늘 ~ 6일 뒤)로 한 번씩 GET. 전체 트리·명단·특이사항은 받지 않습니다. 하루 약 0.1MB 이하(한 팀 150일치가 254KB). 예약 실행은 하루 한 번뿐입니다 — 주기를 늘리거나 기간을 넓히지 않습니다.
- **로그인**: 화면과 같은 익명 로그인. 매일 계정이 쌓이지 않게 끝나면 방금 만든 익명 계정을 지웁니다(인증 계정만, DB 와 무관).
- **일정 ID**: `fsg` + sha256(`날짜|팀|이름|상태`) 앞 40자. 같은 날·같은 사람·같은 상태는 항상 같은 ID 라 중복이 생기지 않습니다. 세부 내용만 바뀌면 같은 일정을 고치고, 상태가 바뀌면 옛 일정을 지우고 새로 만듭니다.
- **삭제**: 이 스크립트가 만든 일정(`fsgMirror=1` 표시) 중 이번 7일 범위 안에서 근무일정표에 더는 없는 것만 지웁니다. 사람이 직접 만든 일정, 지난 날짜의 일정은 건드리지 않습니다.
- **안전장치**: 6팀을 모두 읽은 뒤에만 캘린더를 건드리고, 읽은 칸이 0건이면 지우지 않고 실패합니다.
- **로그**: 건수만 찍습니다. 이 저장소는 공개라 Actions 로그를 누구나 볼 수 있습니다 — 이름·상태를 찍는 코드를 넣지 않습니다.
