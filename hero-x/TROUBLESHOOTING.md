# 문제 해결 가이드

문제가 생기면 먼저 **어느 단계에서** 생겼는지 확인합니다: 설치(`npm install`) → 실행(`npm run dev`) → 브라우저 화면 → 검사/빌드(`npm run check`).

## 설치 단계

### `'npm'은(는) 내부 또는 외부 명령, 실행할 수 있는 프로그램... 아닙니다` / `npm: command not found`
- 원인: Node.js 가 설치되지 않았거나 터미널이 설치 전에 열려 있음.
- 해결: https://nodejs.org 에서 LTS 설치 → 터미널을 완전히 닫고 새로 연 뒤 `node -v` 확인.

### `npm ERR! code ENOTFOUND` / `network` 오류
- 원인: 인터넷 연결 또는 회사 네트워크 차단.
- 해결: 인터넷 연결 확인 후 다시 `npm install`. 회사 PC 라면 집 네트워크에서 설치 후 `node_modules` 폴더째 사용 가능.

### `npm : 이 시스템에서 스크립트를 실행할 수 없으므로 ... npm.ps1 파일을 로드할 수 없습니다` (PSSecurityException)
- 원인: Windows PowerShell 의 기본 실행 정책이 `.ps1` 스크립트 실행을 막음. npm 은 PowerShell 에서 `npm.ps1` 로 실행되기 때문에 막힌다.
- 해결(권장, 한 번만): PowerShell 에서 아래를 실행하고 `Y` 입력.
  ```
  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
  ```
  현재 사용자 계정에만 적용되고, 설치된 도구의 스크립트는 허용하되 인터넷에서 받은 서명 없는 스크립트는 계속 막는 일반적인 설정이다.
- 대안: 명령에 `.cmd` 를 붙인다. `npm.cmd install`, `npm.cmd run dev`.

### `cd : 'C:\Users\이름\Desktop' 경로는 존재하지 않으므로` (바탕 화면 폴더 없음)
- 원인: OneDrive 를 쓰는 PC 는 바탕 화면이 `OneDrive\바탕 화면` 에 있다.
- 해결: 바탕 화면 대신 `cd $HOME` (사용자 폴더)에서 작업한다. 게임 폴더는 `C:\Users\이름\Sysmex-schedule\hero-x` 가 된다.

### `npm ERR! EPERM` / 권한 오류 (Windows)
- 해결: 터미널을 닫고 다시 열어 재시도. 계속되면 `node_modules` 폴더를 지우고 `npm install`.

## 실행 단계

### `Cannot find module 'three'` 또는 `vite: command not found`
- 원인: 라이브러리가 설치되지 않음 (`node_modules` 없음) 또는 `hero-x` 폴더가 아닌 곳에서 실행.
- 해결: `cd hero-x` 로 이동 후 `npm install`, 그다음 `npm run dev`.

### `Port 5173 is in use` (포트가 이미 사용 중)
- 원인: 이전에 켠 개발 서버가 아직 켜져 있음.
- 해결: 그 터미널에서 `Ctrl + C`. 또는 `npm run dev -- --port 5174` 로 다른 포트 사용 (주소도 5174 로).

### 터미널에 빨간 글씨로 `error TS....`
- 원인: TypeScript 타입 오류 (코드 수정 중 실수).
- 해결: 메시지의 파일명과 줄 번호를 확인. Claude Code 에 오류 메시지를 그대로 붙여 넣고 수정을 요청.

## 브라우저 화면

### 화면 위에 빨간 상자 "게임을 시작할 수 없습니다 … WebGL"
- 원인: 브라우저가 3D(WebGL)를 쓸 수 없음.
- 해결: 최신 Chrome/Edge 사용. 설정 → 시스템 → "하드웨어 가속 사용" 켜기 → 브라우저 재시작. 원격 데스크톱·가상 머신에서는 3D 가 꺼져 있을 수 있음.

### 화면 위에 빨간 상자 "게임 실행 중 오류가 발생했습니다"
- 원인: 실행 중 코드 오류.
- 해결: `F12` → Console 탭에서 `[HERO X]` 로 시작하는 메시지와 빨간 오류를 복사해 Claude Code 에 전달.

### 키를 눌러도 움직이지 않음
- 안내 화면이 열려 있어도 키 입력은 동작합니다. 그래도 안 되면:
  - 브라우저 화면을 한 번 클릭해 포커스를 줍니다.
  - 주소창이나 입력창에 커서가 있으면 게임 키가 무시됩니다.
  - `src/game/GameConfig.ts` 의 `controls` 가 비어 있지 않은지 확인.

### 화면이 뚝뚝 끊김 (FPS 가 낮음)
- `src/game/GameConfig.ts` 에서 `graphics.shadows` 를 `false` 로, `graphics.maxPixelRatio` 를 `1` 로 바꿔 봅니다.
- 노트북이면 전원 연결 후 고성능 모드. 브라우저 하드웨어 가속 확인.

### 메뉴에 "저장 데이터가 손상되어 새로 시작합니다"
- 원인: 브라우저 저장소의 `hero-x.save` 값이 깨짐 (브라우저 오류, 외부 도구로 편집 등).
- 결과: 게임은 처음 상태로 시작하고, 깨진 값은 `hero-x.save.corrupt` 키에 그대로 보관됩니다.
- 복구 시도: `F12` → Application → Local Storage → `http://localhost:5173` 에서 `hero-x.save.corrupt` 값을 복사해 Claude Code 에 전달하면 어디가 깨졌는지 확인해 줍니다.

### 메뉴에 "더 새로운 버전의 게임에서 만든 것이라 읽지 않습니다"
- 원인: 최신 버전으로 저장한 뒤 옛 버전 코드를 실행함 (예: `git checkout` 으로 되돌림).
- 해결: `git pull` 로 최신 코드를 받으면 그대로 읽힙니다. 옛 버전을 계속 쓰려면 `새 게임` 을 누르면 덮어씁니다 (기존 저장은 사라짐).

### 이어하기가 비활성이거나, 닫았다 열면 진행이 사라짐
- 사생활 보호(시크릿) 창이나 "쿠키·사이트 데이터 차단" 설정에서는 저장이 되지 않습니다. 메뉴 아래에 "이 브라우저에서는 저장이 되지 않습니다" 가 보입니다. 일반 창에서 실행하세요.
- 다른 브라우저나 다른 PC 에서는 이어지지 않습니다 (저장은 브라우저 안에만 있습니다).
- 주소가 다르면(`localhost` ↔ `127.0.0.1`, 포트 변경) 다른 저장소로 취급됩니다. 늘 같은 주소로 여세요.

### 휴대폰에서 조이스틱·버튼이 안 보임
- 메인 메뉴·결과 화면에서는 원래 안 보입니다. 던전에 들어가면 나타납니다.
- 설정 → 게임 → `터치 조작`이 꺼져 있으면 켭니다. (PC 브라우저에서는 기본 꺼짐)

### 휴대폰에서 화면이 갑자기 커짐(확대됨)
- v0.6.5 부터 두 손가락 벌리기·더블탭 확대를 막습니다. 이미 커진 상태면 **새로고침** 한 번이면 돌아옵니다.
- 그래도 커지면 홈 화면에 추가해서(Safari: 공유 → 홈 화면에 추가) 여세요. 전체 화면 앱처럼 열려 브라우저 확대가 없습니다.

### 휴대폰에서 화면이 스크롤됨
- 최신 Chrome/Safari 로 열고, 가로 모드로 돌립니다. 홈 화면에 추가해서 열면 브라우저 막대 없이 전체 화면이 됩니다.

### 휴대폰에서 많이 끊김
- 설정 → 화면 → `렌더 해상도`를 0.6 으로, `그림자` 끄기, `피해 숫자 표시` 끄기.

### GitHub Pages 주소가 404
- 저장소 → Actions 에서 "HERO X 게임 배포" 가 성공했는지 확인합니다. 실패했으면 로그를 Claude Code 에 전달하세요.
- 저장소 → Settings → Pages 가 `main` / `/ (root)` 로 되어 있어야 합니다. 바뀐 뒤 1~2분 기다립니다.
- 주소는 대소문자까지 정확히: `https://balhm12.github.io/Sysmex-schedule/game/` (S 는 대문자, 끝에 `/game/`). 휴대폰 브라우저가 주소를 자동 완성해 `balhm12.github.io` 만 남기면 "There isn't a GitHub Pages site here" 404 가 뜹니다.

### 캐릭터가 장애물에 끼거나 벽을 통과함
- `GameConfig.world.obstacles` 의 항목이 시작 위치(0,0)와 겹치면 안 됩니다 (`npm test` 가 확인해 줍니다).
- `player.radius` 가 너무 크거나 작지 않은지 확인 (0.2~2).

## 검사·빌드 단계

### `npm test` 실패
- 출력에서 `✗` 또는 `FAIL` 이 붙은 테스트 이름을 확인합니다. 설정값을 바꾼 뒤라면 `tests/config.test.ts` 의 규칙(장애물 크기 > 0, 시작 위치와 겹침 없음, 기본값이 허용 범위 안)을 어겼을 가능성이 큽니다.

### `npm run build` 실패
- 먼저 `npm run typecheck` 를 실행해 타입 오류를 고칩니다. 그래도 실패하면 오류 전문을 Claude Code 에 전달합니다.

## 그래도 해결되지 않으면

아래 정보를 함께 Claude Code 에 전달하면 빠르게 해결할 수 있습니다.
1. 실행한 명령어
2. 터미널 또는 브라우저 콘솔(F12)의 오류 전문
3. 마지막으로 바꾼 파일
